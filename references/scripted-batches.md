# 脚本连续恢复与校验，AI 在批次结束后集中处理未决候选

适用：恢复路线、样本/映射和目标范围已经明确，需要连续处理大量文件。先保全易失材料并完成必要的路线适配；同一已验证布局不为每个目录、每轮进度或每个小批次重复做试验。

## 分工与调度

- **agent 一次确定**：已选目录清单、优先级、取消项、独立目的盘与空间、恢复路线、验证条件、脚本版本及合理并发。沿用 SSH 或 Telnet；不要求切换协议，也不在源卷写作业、日志或恢复结果。
- **脚本连续执行**：按清单批量读取/导出、落盘、独立 SHA 与完整格式/原件校验、保存逐项收据、进度和异常。普通单文件失败留记录并继续其他文件，不等待 agent 逐项批准。
- **AI 默认在批次结束后介入**：一次读取脚本生成的分组摘要，按原因/格式核查少量代表项，为未决文件查副本、旧根、extent、密钥或格式线索。将有依据的补充清单交给脚本继续处理；不逐项调用 AI、不轮询每条候选错误、不重新扫描已验收文件。
- **整体异常及时处理**：作业条件改变、存储/权限/空间异常、断流、取消、执行器整体故障或足以改变当前路线的新材料，依据脚本真实状态及时处理。正常文件格式失败、推测/部分结果与未支持格式留待集中审查；不把这些普通候选问题当作全批暂停理由。
- **进度由脚本与查看器显示**：必要的会话更新仅使用最新小快照/汇总；不要借更新进度反复读历史日志、重新盘点源目录或拆批次。静止快照可能是大文件读取/解码，先检查任务状态与真实 I/O。

批次按实际源布局、目的盘、权限、容量和验收条件组织。脚本内部有界任务队列属于执行细节，不需要 agent 按每2个、10个或几十个文件反复启动新任务。只有范围/布局变化或出现实质风险，才暂停相关组；其他已确认组继续。

## 已保存 Btrfs 导出归档的连续流水线

`recovery_batch.py` 接入本技能现有 Btrfs 导出格式：一个未压缩 TAR 中包含 `_c3r_manifest.jsonl` 和各候选成员。它在独立分析机依次检查完整外层 TAR（header、全部成员长度、终止块与零尾部）、解包、并行校验。外层检查不提前解码候选 payload；单个候选归档损坏应在后续文件校验中登记，不能阻断其他文件。外层截断或非零尾部仍拒绝解包。

```sh
python -X utf8 scripts/recovery_batch.py --export export.tar --output new-batch-recovery --workers 2 --known independent-originals --progress-file new-batch-progress.json
```

没有独立原件时省略 `--known`，仍进行支持的完整格式测试，未检查格式的文件保留未验证状态。未知/推测/部分结果不计为完整恢复；同一源文件的坏 prev 候选在另一个候选已通过原件对照时，不单独触发人工异常。

当前流水线使用保存的 Btrfs TAR，不自动连接 NAS、执行 Solar、进行数据库还原或运行用户程序。在线 Btrfs 按完整已选清单用 `mkjob.py --list ... -- extract @LIST ...` 导出，可靠传输到独立主机后交给本流水线。Drive、密钥解密、离线 extent 等路线使用相应已审阅执行器批量运行；不能声称此 TAR 流水线已通用于全部格式和工具。

查看进度：

```sh
python -X utf8 scripts/recovery_progress.py watch new-batch-progress.json
```

省略 `--progress-file` 时创建独立任务快照，路径记在 `batch-state.json` 中。查看器刷新不触发 agent 调度或额外源盘扫描。

## 中断与继续

批次完成后自动生成私有 `ai-review-RUN_ID.json`，位置记在 `batch-state.json` 的 `ai_review_file` 中。脚本不调用 AI 或外部服务；AI 默认只在这一交接点读取摘要。

批次根目录保存 `batch-state.json`，候选目录保存 `_validation_journal.jsonl`、`_summary.json`、`_best.jsonl` 和 `_exceptions.jsonl`。

```sh
python -X utf8 scripts/recovery_batch.py --export export.tar --output new-batch-recovery --resume --workers 2 --progress-file resumed-batch-progress.json
```

- **校验阶段中断**：保留导出与解包结果，继续校验；原件目录从检查点继承。逐项校验结果实时落日志，不到结束才保存。
- **源文件已校验且字节未变**：继续校验时仍回读当前候选 SHA 和必要的原件 SHA；仅复用与同一记录、验证器版本和字节对应的成功完整解码，避免重复耗时解码。元数据相同不能代替当前内容摘要。
- **字节、原件或验证条件变化**：不沿用原来的通过结论。增加新的 `--known` 目录时可重新执行校验；其他新线索针对相关项生成补充任务，不把整批已完成文件反复排队。
- **批次已经完成**：`--resume` 返回 `already_completed` 和原验证时间，明确 `new_checks_run=false`；这是历史收据，不宣称重新检查了后来变化的文件。要重新检查现有候选，用下方校验命令。
- **导出/解包阶段中断或源归档变化**：保留部分结果，不覆盖源文件或已写成员。更换新批次目录重试有证据支持的导出；不能宣称实现了任意断流 TAR 的字节级续传。

对现有候选目录继续检查：

```sh
python -X utf8 scripts/c3r_local.py validate new-batch-recovery/candidates --resume --workers 2 --progress-file resumed-validation-progress.json
```

省略 `--resume` 会重新做完整检查。每次恢复使用新的进度文件，既有工作结果与检查点均保留。批次根目录的 `_batch.lock` 在读取检查点前取得 OS 锁，覆盖归档检查、解包、校验及最终收据；候选目录另有 `_validation.lock`，防止独立校验器同时进入。竞争进程失败时不改写活动任务的状态或进度；锁由 OS 在进程退出后释放，残留锁文件不意味着任务仍在运行。

## 批次结束后的 AI 摘要

流水线自动调用 `summarize_exceptions.py`。已有完整校验清单也可单独汇总：

```sh
python -X utf8 scripts/summarize_exceptions.py --input new-batch-recovery/candidates/_exceptions.jsonl --output new-private-ai-review.json
```

输入要求来自同一运行且标记 `source_complete=true` 的完整 JSONL 收据，默认在校验批次结束后使用；截断、混合运行或未完成源文件会拒绝。输出使用新文件名，放在独立私有目录中，Windows 同时检查目录 ACL。

摘要按问题类别和格式分组、累计条目数，默认最多展示12组、每组3个代表项，可用 `--max-groups` 和 `--representatives` 调整。保留原始详细记录的行号/字节偏移，长路径和错误信息只在摘要中截短，原收据不修改。未展示组和条目单独计数，仍属未决；没有异常时 `ai_review_needed=false`，不发起 AI 审查。1000条同类合成异常可归为1组3个代表项，这只是摘要压缩示例，不是实际模型费用或恢复成功率测量。

AI 先读分组摘要；需要细节时按代表项偏移读相应私有收据，不把整个日志重新载入上下文。完成集中判断后，为有新线索的未决源文件列出补充清单、适用路线、证据与停止条件，交给对应已审阅脚本。新材料不足的对象保持未决，不自动无限重试；本脚本不内置覆盖所有恢复路线的重试执行器。

## 异常与验收

`_exceptions.jsonl` 在当前运行开始时重建；每个源文件的所有候选完成后立即写入并 flush，包含 `source_complete=true` 和 `validation_run_id`。同一源文件早期坏候选不会在好候选尚未完成时触发人工异常。实时写入用于保留证据和支持查看器，不要求 AI 实时消费。默认待整批完成，交由脚本流式聚合为摘要后再让 AI 集中分析。运行中没有异常记录不代表整批完成，完成以批次状态为准。

该清单只列出未解决的源文件：导出未取得、校验失败、未知格式、推测/部分结果及未适配异常。worker 的普通读取/解析异常转为失败项，其他任务继续；执行器整体故障保存检查点后交给 agent。

支持的图片逐帧/逐页 load，ffmpeg 映射全部音频与视频流；字幕、附件、业务语义和历史字节一致性不属于媒体解码证明。TAR/gzip 候选使用完整归档审计，未支持格式仍保留未验证。

候选经过完整解码或原件对照后再次回读 SHA，并检查设备/inode/大小/时间变化；同版本原件匹配时同样复读其内容，防止保留 mtime 的写入被当作通过。此步骤增加必要的 I/O；SHA 与格式检查仍是该次检查的收据，验收期间保持候选及原件静止，后续改写需重新校验。成功解码的续查可复用原收据，当前内容核对仍保留。

AI 从分组摘要选出值得处理的组，先查默认最多3个代表项，标明原因、已有证据、新线索和下一步。一个方案在代表项上证实适用后，相关组由脚本按补充清单批量处理，不为每个文件重新推理。没有新材料，不自动无限重试同一个失败对象，也不重审所有成功日志。已完成/已取消任务不重新入队；多个候选按原文件身份去重。

`completed` 表示本流水线没有所列未决源文件；`completed_with_exceptions` 表示正常流程已跑完但还有未决项，CLI 退出码2。退出码0、文件总数和100%阶段进度都不单独证明全部数据、映射或业务完整。报告继续注明原件 SHA、完整格式、源块校验及业务检查各自的覆盖范围。
