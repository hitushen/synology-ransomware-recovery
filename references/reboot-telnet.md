# 重启、重新安装提示与 SSH / Telnet 救援

适用：用户提供 SSH 或 Telnet，或重启后 DSM 显示重新安装、已重置或未安装，需要保留源盘并通过现有管理入口调查。

SSH 与 Telnet 都是可用入口。先沿用用户已经提供、当前可连接且已授权的协议和会话；无需同时具备两种入口，也不要求为满足协议偏好启用其他服务。Telnet 的传输限制按下文处理。

## 入口判断

1. 使用当前已知 IP，核对本机路由、ARP/DHCP 或可信虚拟化控制台。IP 可能在重启后变化；不为寻找设备盲扫不相关网段。
2. 已有可用会话时直接继续只读检查；入口未知或失效时，对指定主机做有界 TCP 检查：`scripts/probe_rescue_ports.py --host 192.168.200.2 --output NEW_JSON` 默认检查 23、22、5000、5001，**不登录、不发送命令、不打开服务**。端口开放只说明 TCP 可连接；端口号不是服务身份或可信性证明。ICMP 不通也不证明设备离线。
3. 沿用用户提供的 SSH 或 Telnet 地址、实际端口和已授权账号，确认设备身份后登录。入口未知时，23/Telnet 与 22/SSH 都可检查；端口可能不是默认值，不以偏好固定先后。Telnet 使用隔离管理链路；root 空密码只用于所有者明确说明的现场，不能套用到其他设备。当前入口确实不可用时再检查另一入口或可信控制台，不为启用服务重装 DSM。
4. 无入口时保留电源与现状，检查控制台和网络层。需要变更硬件或断电且当前授权不足时，说明具体原因再询问，不先破坏现场。

`192.168.200.2` 的既往事实：攻击后已重启，系统提示已重置，仍能通过既有已授权的 Telnet 入口进入 BusyBox 救援 shell；数据卷未挂载，数据阵列未组装。救援入口不能恢复已丢失的旧进程内存。

## 登录后先读状态

在当前授权内执行必要的只读查询，输出保存在独立主机。缺少命令就记录，不安装套件到源池。

```sh
id
uname -a
cat /etc/VERSION
cat /proc/uptime
cat /proc/mounts
cat /proc/mdstat
cat /proc/partitions
cat /proc/swaps
ps
```

按发现的**实际成员路径**读取 `mdadm --examine MEMBER`，比较阵列 UUID、level、成员角色、Events、clean、data offset、bitmap 与 reshape 标记。按需只读查询 device-mapper/LVM。不要照抄案例设备号或偏移。

区分正常 DSM 且卷已挂载、救援系统且卷未挂载、部分阵列/缓存缺失、盘故障或状态不一致。只读打开文件不停止后台写入；未组装源盘不因“恢复”而自动 assemble、mount、repair。

## 离线读取条件

- 同代 clean RAID1 成员可作为相同字节的读取来源，但必须验证 data offset、后续 LVM/device-mapper/缓存及 Btrfs 起点。RAID1 冗余不会撤销同步的勒索写入。
- 比较成员超级块/FSID/代数与同位置元数据。有差异、reshape、旧成员或条带层，停止通用单成员方案，另做存储层重组。
- `dd` 仅用数值验证过的 `if`、offset/count，输出通过字节安全链路送独立主机，不向受灾盘指定 `of`。保存设备、原始字节偏移、长度、时间、SHA 与退出状态。
- Btrfs 的 `ro` 可能回放日志，ext4 普通 `ro` 也不能代替禁止日志回放。需要挂载时针对副本与真实版本设计 no-log-replay 条件，不在原盘试验。
- Telnet 有协商字节、CR/LF 和回显，不直接传原始归档。只有 Telnet 时仍可继续：用已有 hex/base64 能力分块编码，在独立接收端解码，每块记录偏移、长度、边界与 SHA，完整文件再核对总长度和摘要；或使用经核实可用的受控单次传输。中断块单列未验收，不把回显、提示符或诊断混入数据；不向源盘落中间文件，不要求用户另开 SSH。

结束重新读源状态，报告挂载、Events/clean、超级块代数是否变化。重启后 RAM/swap 只描述当前状态；旧 dump 才是重启前现场，磁盘 swap 残留仍可按真实写入情况评估。
