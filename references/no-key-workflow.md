# 无有效密钥：副本、快照与旧块

适用：已重启且未保存旧 RAM，候选材料不匹配，或现有解密器不适配。未重启时先保全可取得的易失材料。没有新证据时不要无限重复同一 RAM/公共候选扫描。

## 先找可验证的独立原件

1. 查用户已有外接盘、电脑/手机、云端、历史备份。查原共享之外的 **Synology Drive 历史/当前 repo、ABB 仓库、VMM 克隆与导出、Photos 缩略图、回收站和隐藏目录**；记录来源与版本，不能因为目录以 @ 开头就完全跳过。
2. Drive repo 的对象名可能不保留原始文件名，也可能没有 .L0CK3D 后缀。使用已知加密前长度、格式、时间和索引关系筛选候选；大小/文件头相同只用于筛选，不证明同一内容。
3. 优先使用当前可达的未加密副本；验证候选全部未加密范围与目标关联，检查其完整映射、源块校验和（适用时）、全格式流和导出/回读 SHA。可达 repo 对象可能让部分旧块路线失败的大文件完整恢复。
4. 缩略图/转码视频只能作为替代版本；像素等价与字节精确恢复分开，不能拿低清替代原件而声称原件完整恢复。

## 进一步提高找回机会

按现有线索选择路线，不把下面的方法当成通用成功保证。先调查副本与历史版本；镜像解析、雕刻和介质采集都需要对应材料或问题证据。

| 路线 | 值得检查的材料 | 可以达到的结果与限制 |
|---|---|---|
| 客户端与协作副本 | Drive 客户端离线目录、未同步的电脑/手机、邮件附件、应用导出、协作方已有副本 | 可能找回完整原件或较旧版本；先避免受影响同步覆盖这份副本，不自动重连同步 |
| 外部与异地备份 | Hyper Backup 仓库、USB/远程 NAS、云端对象版本、对象锁历史、Time Machine 与其他既有备份 | 核对攻击前版本、索引、密码/备份密钥及全部数据块；在独立环境还原，元数据可读不等于正文完整 |
| 事故前已离线的磁盘成员 | 在攻击前已断开或退出的旧 RAID 成员、历史镜像、独立复制盘 | 先核对时间、阵列 Events、代数和完整存储层，只读取得副本；在线 RAID1 会同步加密，不将旧成员重新加入原阵列 |
| 其他文件系统历史与删除记录 | 独立镜像上的 Btrfs backup roots、ext4 inode/目录/日志、现存快照和回收站 | 能提供历史映射与部分数据线索；日志不是完整备份，NoCOW 覆盖或已回收/TRIM 的数据可能无旧正文 |
| 文件特征恢复 | 独立镜像或明确范围内仍有未加密字节，文件系统目录映射不足 | 可选 PhotoRec/TestDisk 或针对格式的雕刻；不能从完全加密的字节凭空还原原件，碎片化/压缩/分段大文件可能不完整，名称和目录也可能丢失 |
| 物理读错误处理 | 坏扇区、掉盘、读错误及对应磁盘/镜像 | 由支持者在独立目标上用 ddrescue 和 mapfile 保存可读范围，减少无意义重读；不写源盘、不为此自动断电，采集改善不等于破解加密 |
| 应用级重建 | 独立数据库备份、WAL/binlog、对象存储、版本库、容器卷与应用导出 | 可在干净兼容环境重建部分业务；先验证基线、日志连续性和事务一致性，单列业务恢复与事故前原文件精确恢复 |

PhotoRec/TestDisk 与 ddrescue 是可选外部工具，本技能提供选择与验收指引，没有附带它们的程序。参考 [CGSecurity 文档](https://www.cgsecurity.org/wiki/TestDisk)和 [GNU ddrescue](https://www.gnu.org/software/ddrescue/)。不在受灾盘运行写入、修复分区表或原地恢复模式，也不为了增加“成功率”启动原系统或运行勒索样本。

为每条采用的路线保留来源、时间/版本、读取范围、工具与参数、输出位置及验收证据。已验证完整原件、已验证较旧/替代版本、仅候选、部分恢复和未验证项分别汇报。没有新线索就转向下一条有证据的路线，避免反复全盘雕刻。

## 快照与历史根

分别盘点现存只读子卷、共享快照、Drive/ABB 版本和超级块 backup roots。`last_snapshot > 0` 只说明历史快照线索，不证明现在有可用攻击前快照，更不证明不可变保护。

Docker 可写克隆/VMM 子卷不是天然的共享快照；PVE 快照不会自动包含直通 HBA 上的数据盘。对历史根验证 generation、FSID、逻辑地址、元数据 CRC 和引用完整性，不能认为“旧根”一定在攻击前，或能撤销同一物理块的 NoCOW 覆盖。

## 内置 Btrfs 工具

原理见 [上游原理](btrfs-principles.md)，环境问题见 [兼容说明](btrfs-compatibility.md)，异常见 [常见问题](btrfs-pitfalls.md)。这些是上游历史资料；本技能的 [验证边界](btrfs-recovery_CN.md) 与实际检查结果优先，不能沿用“标签 exact 即历史原件正确”“失败小文件永无可能”等绝对结论。

挂载模式：`preflight` → `env` → 跨共享采样 `gens` → 已知原件单文件 `plan/extract/csum` → `survey` → 小批导出/验收 → 按需扩大。`scripts/mkjob.py` 与 `c3r_btrfs.py` 在同一目录，作业由 stdin 送可信入口，输出由独立主机接收。

- `preflight` 有的 FAIL 会返回退出码 0，检查各项实际内容，必须通过所需端到端映射与校验和自检；被跳过的检查不能算通过。
- 该上游 Btrfs 规划器的 `formula_ranges` 只支持分段 0x25 参数 **10**；本技能 `file_layout.py` 的算法还覆盖已逆向的其他参数，但不能凭这个直接宣称 Btrfs 规划器已支持参数20。遇到不同参数，适配真实边界、尾部和全部映射，再用独立正负例及源样本验证。
- 原生 RAID0/10/5/6、压缩、inline 和不完整元数据不在普通线性路径内。DSM 底层 RAID1 不等于 Btrfs 数据 profile RAID1；必须读真实 chunk/profile。
- G_ATTACK 必须从不同文件/共享的正常与攻击代数推定并核验边界。历史 Data/备份阈值不能通用于全卷。
- 工具可能在 /tmp 建临时文件，不能宣称完全不写现场；核对临时挂载和私有目录。不能绕过工具拒绝、裁掉自检或选择 stripe0 来假装适配。

### 未挂载救援卷：独立离线分支

不为运行上游 ioctl 规划器而组装/挂载源盘。基于 [救援入口](reboot-telnet.md) 已证实的存储层，从确定范围获取原始副本，再离线解析：

1. 验证 Btrfs 超级块与副本 CRC、FSID、sector/node size、checksum type、chunk 逻辑到物理映射和源分区起点。
2. 验证每个树节点的 CRC/FSID/bytenr/level/代数，按 ROOT_ITEM 与 EXTENT_DATA 重建 inode 的映射。标准 ROOT_ITEM 的 `last_snapshot` 在结构内偏移 **200**；确认结构版本与有效长度，不能误读相邻字段。优先保存原始数据和可复核解析证据。
3. 在相关设备/冗余副本上读取样本，证明映射读出的当前范围与目标文件字节一致。旧范围分类必须结合原始 disk_num_bytes、extent offset、未改写边界与文件归属，不能只凭物理相邻。
4. 输出逐段计划：file offset/length、logical、physical/member、generation、来源树/节点、校验覆盖与缺失范围。不得把未知 gap 当稀疏零；preallocated、inline、压缩各需专门处理。
5. 旧叶雕刻只扫描与目标有关的、已获得或明确范围限定的 metadata；验证完整节点再使用历史引用。缺口、坏节点、另一 DUP/RAID 副本仍失败时留收据；不要盲扫无关整盘。
6. prev/next 外推只作为候选；格式/CRC 失败不能靠填零晋升。全块 checksum 只证明所选块与记录一致，旧块所属历史文件仍需映射/边界证据。

## ABB 与虚拟机

- ABB 备份不是普通完整镜像：先识别版本、catalog/数据库、分块/去重关系、包完整性及缺失 chunks。元数据能列出备份不等于全部 payload 可读。保存原始目录结构，在干净兼容环境验证还原能力；不要在受灾 NAS 重装 ABB 来读仓库。
- 加密虚拟磁盘整体难恢复时，可以在独立受损盘副本中只读解析客体 GPT/LVM/ext4；验证超级块、组描述符、inode/日志 CRC，映射尚存文件并逐文件检查。ext4 元数据 CRC 不验证普通正文。
- 日志 inode/目录名为历史候选；根目录数据缺失时用可逆编号名，不猜成 /root 或 /opt。文件未落入已知加密范围也可能另有损坏，仍需内容检查。
- 恢复大量客体文件不等于完整虚拟机。受损 raw 不能标为可启动原盘或直接转成“成功 OVA”；干净系统重建/业务恢复与原机字节恢复分开验收。

流程结束提供哪些是完整副本、哪些是已验证旧块、哪些仅替代版本/部分文件、还缺哪些材料。保持原密文和源成员，不在恢复未完时拿 RAID1 另一成员当输出盘。
