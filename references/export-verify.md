# 批次、目的盘与验收

## 盘点与分配

按当前授权的目标目录盘点普通文件、目录、特殊对象、硬链接、快照/历史版本，记录分母。路径数不等于独立 inode 数，去重块逻辑总量不等于实际磁盘占用。先提供目录清单供用户选择；已选范围、明确取消项与完整性要求持续生效。

空间估算分别给最终文件逻辑大小、临时副本/候选/压缩归档、验证和安全余量；不默认要求落完整全盘镜像，也不能把局部采集称为全盘保全。稀疏大磁盘在不同目的文件系统可能占用不同空间。

若用户选择多个目的盘及目录归属，保存唯一分配表，以指定目录为核算单位，包含临时和最终空间。按总账预留空间，再开始批次；候选区与验收目录分开，已有验收文件不得覆盖。文件名保留可逆映射，处理 Windows 保留名、大小写冲突、长路径、非法字符和源编码；不跟随符号链接。

多个 worker 仅在用户或适用工作流程明确授权时使用；共享源身份/工作 claim/accepted ledger 排他调度，避免同一 inode 并发导出、撞盘或覆盖。旧会话的 E/F 分配不自动适用于新任务。

## 传输

沿用用户提供的 SSH 或 Telnet，两者均可下发适用的恢复命令。协议选择与数据完整性分别处理；只有 Telnet 时也继续当前授权内的工作，不以工具偏好要求换成 SSH。

SSH 的 stdin 可传作业脚本，stdout 可传 tar/gzip 二进制，stderr 保存诊断。用 Python `subprocess` 字节流或已经验证的原生重定向，不要把二进制经过文本解码。PowerShell 版本与 native 到 native 是否保字节有差异，**不假定任意管道都安全**；Python 的二进制文件句柄最稳定。

```python
# 示例仅展示字节安全形态；实际命令、主机、权限及输出路径先确定。
import subprocess
with open('job.sh', 'rb') as job, open('new-export.tar', 'xb') as out, open('new-stderr.log', 'xb') as err:
    result = subprocess.run(['ssh', 'USER@HOST', 'sh -s'], stdin=job, stdout=out, stderr=err, text=False, encoding=None)
if result.returncode:
    raise RuntimeError('Transfer failed; keep output as unaccepted candidate')
```

`mkjob.py` 生成 LF 脚本，避免超长 SSH 命令行。密码走交互或受控凭据机制，不放命令行。Telnet 二进制协商、回显和 CR/LF 可能改字节，原始终端流不能直接当 TAR。可使用现有 hex/base64 能力分块发送，独立接收端只解码有明确边界的数据段，逐块核对偏移、长度和摘要，再核对完整文件；或使用已核实可用的受控单次传输。无需为此切换到 SSH，也不向源池写临时归档。断流或摘要不符的块单列未验收，失败归档不当完整结果解包。

用 `c3r_local.py` 前检查当前参数和归档成员安全：拒绝绝对/逃逸路径、链接、覆盖与候选/manifest冲突，确保所有解析输出在新目的目录内。不执行导出的程序。

本技能集成版 `c3r_local.py extract STREAM NEW_DIR` 必须使用尚不存在的新输出目录，会拒绝覆盖、重复成员、链接与越界路径。失败批次保留为未验收，不向已有目录重跑；改用新批次目录并在总账去重。Windows 不可表示的源名字需先做可逆映射，不删除字符强行合并。

## 完整验收的层级

| 证据 | 能说明什么 |
|---|---|
| 导出 SHA 与独立本地回读 SHA 一致 | 传输和落盘一致，不证明历史原文正确 |
| 全范围源块 CRC32C 与有效 checksum tree 记录一致 | 所检查字节与对应校验记录一致；需映射/历史关联，列出 bad/missing/覆盖数 |
| 独立同版本原件的全 SHA／逐字节一致 | 该文件精确恢复 |
| 完整 gzip/XZ/ZIP/7z/TAR 检查或全部音视频解码 | 通过此格式的完整性测试；业务和历史字节仍需相应证据 |
| 数据库在干净副本恢复并做应用检查 | 通过所列业务验收，不等于业务内容无历史遗漏 |
| 文件头、预览、UTF-8/语法解析、像素等价 | 各自的有限证据，不自动等于完整原件 |

gzip 必须读至 EOF 并核对 CRC/ISIZE、截断与额外流；TAR 验证每个 header、成员实际长度、终止块与尾部，不能以列出目录代替读全 payload。数据库、VM、容器按真实版本验收；容器 rootfs 导出可能遗漏 bind mounts，完整归档不证明备份制作时包含全部业务。

集成版 `verify_backup.py FILE.tar[.gz]` 审计完整 TAR 结束与零尾部，gzip 拒绝截断、拼接流和额外字节；嵌套归档同样检查。`c3r_local.py validate NEW_DIR` 重新回读当前输出 SHA，未检查格式单列 unverified，已知原件不匹配不算通过。其他格式不支持时执行对应验证器并记录；不得把没有正文验证的文件强行接受。

Btrfs 全块验收注明 sector size 和最后一个扇区原始 padding；`bad=0` 但 `missing>0` 不是全覆盖。NoDataSum 无正文校验和，不伪称 CRC 通过。`self_ok=0` 不是自检成功。格式报错不能仅凭 exact 标签归为原件固有损坏。

逐文件保存 source identity/route/size/输出摘要/独立回读/块覆盖/格式测试/历史对照/业务检查/限制。用户只接受完整结果时，填零、缺段、推测及跳错解包文件留独立候选区；不要改名去掉 partial 来假装成功。

结束以实际收据统计完整、替代版本、候选、失败、取消与未决，报告目的位置和原盘状态。任务日志用恢复进度与剩余不确定性表达，不重复把程序已启动当完成。
